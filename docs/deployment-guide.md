# Deployment Guide

Use this guide when deploying `creativecrafts/laravel-sso` to staging or production.

## Pre-deploy checklist

1. Confirm the target application runs a supported PHP and Laravel version.
2. Confirm package migrations have been published.
3. Run database migrations in the deployment pipeline.
4. Confirm `APP_KEY` is stable across all app instances.
5. Confirm queue, cache, and session backends are production-ready.
6. Confirm public SSO routes are reachable over HTTPS.
7. Confirm proxy and URL generation settings produce the public application origin.
8. Confirm pruning is scheduled.

## Environment configuration

Minimum production expectations:

```env
APP_ENV=production
APP_DEBUG=false
APP_URL=https://app.example.com
SSO_ENABLED=true
SSO_ROUTES_ENABLED=true
SSO_ALLOW_INSECURE_IDP_URLS=false
SSO_ALLOW_PRIVATE_IDP_URLS=false
```

Only enable insecure or private IdP URL overrides in local development or tightly controlled test environments.

## Database migrations

Run:

```bash
php artisan vendor:publish --tag="sso-migrations"
php artisan migrate --force
```

The package assumes its schema is current. Existing installations should also review `docs/upgrade-guide.md` before deploying a new package version.

## IdP application registration

For each production connection, register the generated callback URLs with the IdP.

OIDC callback route:

```text
/sso/{tenant}/{connection}/callback
```

SAML ACS route:

```text
/sso/{tenant}/{connection}/saml/acs
```

SAML metadata route:

```text
/sso/{tenant}/{connection}/saml/metadata
```

Use the actual public URL generated by the deployed application, including scheme, host, route prefix, tenant, and connection values.

## OIDC deployment notes

- Use authorization code flow with PKCE.
- Configure the final HTTPS discovery, token, JWKS, and userinfo endpoints.
- Do not rely on IdP endpoint redirects.
- Ensure DNS for IdP hostnames resolves to public routable addresses from the application network.
- Rotate client secrets through normal secret-management processes.

## SAML deployment notes

- Configure one or more PEM signing certificates.
- Keep old and new signing certificates configured during certificate rollover.
- Confirm the IdP posts to the correct ACS URL.
- Confirm the SP entity ID matches the IdP audience value.
- Keep destination, audience, recipient, and correlation checks enabled unless you have a specific compatibility requirement and compensating controls.

## Throttling

Public SSO endpoints are throttled by default. Keep throttling enabled unless an upstream gateway provides equivalent protection.

Default buckets:

- `sso.redirect`
- `sso.callback`
- `sso.acs`

## Data retention

Schedule pruning daily:

```bash
php artisan sso:prune --attempts-days=7 --audit-days=30
```

Tune retention values to your organization's support, audit, and privacy requirements.

## Smoke test

After deployment:

1. Run `php artisan sso:doctor`.
2. Start an OIDC login and complete the callback.
3. Start a SAML login and complete ACS if the application uses SAML.
4. Confirm audit records are redacted.
5. Confirm failed callbacks do not consume auth attempts.
6. Confirm stale auth attempts are pruned by schedule.
